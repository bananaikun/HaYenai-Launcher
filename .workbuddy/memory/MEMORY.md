# HaYenai-启动器 · 项目记忆

> 本文件在该工作区打开时被注入。只放硬规则与指针，细节看 `docs/`。

## ⛔ 动手前先问（硬门槛 · 优先于一切）

实质任务（开发/修改/改配置/重构/删改数据）动手前**必须用原生选项卡提问**，未确认前不写代码。

「续做」只免**同一决策点已确认过**。出现下列任一必须重新问：
新增/更换依赖 · 改数据模型 · 删改数据 · 改架构 · 改构建或发布流程 ·
**不可逆操作**（删文件/删分支/force push/改 submodule）· 与主人新要求冲突

长任务**分段确认**：每完成一阶段、进下一阶段前，重新确认 1-3 个决策点。

## 项目事实（省得每次重新摸）

- Monorepo：Turborepo + pnpm workspaces；Vue 3 / Nuxt 3 + Tailwind v3；桌面 Rust / Tauri 2
- **改界面只落 `apps/app-frontend/`**；改窗口/进程/启动落 `apps/app/`；公共组件落 `packages/ui/`
  （改错层会出现「改了没生效」——tauri 打的是 `apps/app-frontend/dist`）
- 缩进一律 **空格，禁止 Tab**
- 提交前跑对应包的 `fix`（ESLint --fix + Prettier --write），只跑 Prettier 不够
- 子模块是构建依赖：`git submodule status` 两个都要有 commit，不能是 `-` 开头

## 历史教训（2026-10-25 主人指出）

- 之前出现「一个 commit 混 4-6 件不相关改动」（如 `55d04ea` 改了 23 个文件）→ **不先问 + 顺手改**
- `docs/requirements/` 一直不存在 → 需求确认阶段从未真正执行
- 结论：先问、先写需求卡、只改相关的文件
