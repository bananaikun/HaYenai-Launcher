## 2. 冒烟（`target\release\HaYenai.exe` 直跑）

1. 进程正常启动，主窗口标题 `HaYenai`。
2. 无崩溃、无「启动器已停止工作」对话框。
3. 三次冷启动（各采样 14 秒）：

| 次数 | 工作集 | 私有字节 | 线程 |
| --- | --- | --- | --- |
| 1 | 113 MB | 58 MB | 67 |
| 2 | 109 MB | 54 MB | 59 |
| 3 | 108 MB | 53 MB | 57 |

与 1.0.50（115/115/113 MB）、1.0.51（117/111/116 MB）同一量级，无回归。

## 3. 回归范围

- 只改 `packages/app-lib/src/launcher/jvm_args.rs`（GC 探测缓存）+ 文档。
- `cargo check -p theseus --no-default-features` exit 0（2m20s，无新增 warning）。
- 缓存实现要点（详见需求卡「GC 探测磁盘缓存」段）：只缓存通过的结果；键含 Java 路径、大小、mtime 与参数；>256 条整体清空；写失败只 warn。

## 4. 未验证项

- **没装机实测「第二次启动少等几秒」**：本机没有可启动的实例环境，缓存收益靠代码路径保证（命中即返回，不再 spawn JVM），未做秒表对比。
- 未验证缓存文件被外部删除/写坏时的行为（代码按「读失败即重建」处理，未跑真实故障注入）。
- 1.0.50/1.0.51 的壁纸静帧、磁悬条进度视图仍需真机点验。

## 5. 发布

- 提交：见 `git log`（`fix(launch)` 一条，含 `release/1.0.52/NOTES.md`、`docs/releases/*`、需求卡）。
- tag：`hayenai-v1.0.52`。
- 推送：`git -c http.version=HTTP/1.1 push pub public-main:main`（本机到 github.com 的 HTTP/2 会被 reset）。
- 发布：`node --use-system-ca scripts/publish-github.mjs`（Node 自带 CA 撞本机 TLS 中间盒，必须用系统证书库）。
